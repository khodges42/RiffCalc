# PACKRAT / Milestone 1 validation

Historical Milestone 1 record. The native workstation is described in
[PACKRAT application docs](../../README.md).

2026-11-06. Generator algorithm `packrat-1`, profile schema 1, software 0.1.0.
This milestone supplies a CLI and library; no PACKRAT plugin or audio callback
exists, so VST3/audio-device/drag compatibility is not claimed or tested here.

## Builds and tests

Windows x64: MSVC 19.37.32825, Visual Studio 2022 C++ tools, Windows SDK
10.0.26100.0, CMake 4.2.3-msvc3, Python 3.14.4. **Debug and Release** build with
`/W4 /WX /permissive- /EHsc /utf-8`. All three CTest suites pass in each:

1. `packrat_core`: **11 test groups**, including all **1,440 root × scale × genre
   combinations**, all 1–16 bar lengths, edge registers, chord/scale spelling,
   sixteen formulas, voice-leading, complexity, cadence, explicit chromatic colour,
   PRNG reference vectors, validation and empty/one-tick/long-delta MIDI cases.
2. `packrat_cli_midi`: independent Python SMF decoding versus generated note data
   for all twelve genres, Type 0/header/track integrity, tempo and meter,
   note-off ordering, note pairing, exact end time, Unicode filenames, protected
   existing MIDI/sidecars, invalid configs/profiles and four SHA-256 golden cases.
3. `packrat_vendor_hashes`: exact vendored header/license source hashes match.

Existing Ubuntu 22.04 / WSL2: **GCC 11.4.0**, C++20, `-O2 -Wall -Wextra
-Wpedantic -Werror`, Python 3.10.12. Core and CLI compile, all 11 core groups pass,
and the same independent CLI/MIDI tests pass. All four fixed MIDI **and metadata**
hashes match Windows Debug/Release exactly. No dependency was installed in Linux.

CMake is absent in that Ubuntu distro. The Linux check used a direct compiler
invocation and the platform-neutral bundled-profile header generated by the
Windows CMake configuration. This verifies source/CLI portability and the tested
cross-compiler fixtures, **not execution of the Linux CMake preset**, macOS,
native Linux GUI or plugin behavior.

The manual Linux compiler invocation, from repository root, used the equivalent
of the following for both CLI and tests (substitute `packrat/tests/tests.cpp` and
an appropriate output name for the latter):

```sh
g++ -std=c++20 -O2 -Wall -Wextra -Wpedantic -Werror \
  -Ipackrat/include -isystem packrat/third_party \
  -Itarget/packrat/windows/generated \
  packrat/src/core/*.cpp packrat/src/style/profiles.cpp \
  packrat/src/midi/midi.cpp packrat/src/cli/main.cpp \
  -o target/packrat/linux-manual/packrat
python3 packrat/tests/integration.py target/packrat/linux-manual/packrat target/packrat/linux-manual/test-output
```

The existing Rust workspace still passes all **87 tests**, formatting, workspace
check, Clippy with warnings denied and its **113-package** license inventory.
PACKRAT's one C++ dependency has a separate checked manifest. No Cargo dependency,
existing plugin DSP/wrapper, DAWJ playback path or session format was changed.

## Engineering limits and next step

Automated checks establish interval/membership/range/timing and serialization
properties. They do **not** prove genre authenticity, pleasing voicings or a good
musical phrase. The examples still need manual audition with chosen instruments.
Voicing is an integer-cost open-phrase optimizer; it is not complete counterpoint
or loop-seam optimization. Generation is 4/4, one chord per bar with genre-specific
retriggers. Only the controlled dominant-colour rule is implemented for borrowed
harmony. Melody, bass and arpeggios are not hidden behind placeholder controls.

Generation, JSON and file export allocate and execute on the caller's non-audio
thread. Future preview must receive immutable prepared clips. No audio-thread
safety is asserted for the generation API. File writes protect existing outputs,
but the MIDI/sidecar pair is not a power-loss-safe transaction.

Stop at **Milestone 1**. Recommended next work is M2's shared JUCE application/
plugin UI, prepared-clip playback, preview synth, persistent config and MIDI file
dragging, with target-host validation. JUCE licensing/dependency pinning and DAW
integration must be evaluated before that implementation. M3/M4 remain deferred.
